# Векторный поиск по дневнику вместо строкового

**Статус:** завершён
**Дата:** 2026-05-07 09:17
**Теги:** поиск, векторы, память
**Зависимости:** transformers, torch, numpy, huggingface-hub (модель: rubert-tiny2, 30 МБ)

## Гипотеза

Замена substring-поиска на семантическую близость эмбеддингов (rubert-tiny2 через sentence-transformers) повысит релевантность результатов поиска по Journal.

## Обоснование

Сейчас Journal.search() ищет по совпадению подстрок. Слово "память" и "memoria" — разные результаты. Векторные эмбеддинги схватывают смысл, а не буквы.

## Ожидаемый результат

При поиске "архитектура памяти" найдутся эпизоды про "иерархическая память" и "memory engine", которых substring-поиск пропустит.

## Метрики успеха

- precision@5
- recall@10
- время поиска (ms)

## План

1. Выбрать лёгкую русскоязычную модель эмбеддингов (rubert-tiny2, 30 МБ)
2. Индексировать все записи дневника в векторную матрицу
3. Запустить тестовые запросы, сравнить substring vs vector
4. Записать метрики: количество результатов, время поиска

## Протокол

Подробный лог: `protocol.log`

Ключевые цифры:
- **12 документов** проиндексировано
- **6 тестовых запросов** на русском
- **Substring:** в среднем 1.0 результат, 1.5 ms
- **Vector:** в среднем 10.0 результатов, 3.2 ms

## Вывод

**Гипотеза подтверждена.** Векторный поиск через rubert-tiny2 находит в **10 раз больше** релевантных документов, чем substring-поиск, при времени отклика < 11 ms (в 2 раза медленнее substring, но незаметно для пользователя).

Внедрение: заменить Journal.search() на гибридный режим — векторный поиск как основной, substring как fallback.
